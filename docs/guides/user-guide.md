# PAD Router 使用指南

這份指南給第一次使用桌面 web UI 的玩家；它說明如何在辨識不確定時安全修正、設定規則、搜尋路徑與執行手勢，維護者可再看[架構](../reference/architecture.md)與[開發指南](../reference/development.md)。

## 1. 啟動與準備

```bash
# 支援的離線桌面 web UI（所有已交付工作流）
uv run python pad_router.py --gui

# --webview 保留為相容別名
uv run python pad_router.py --webview
```

需要：

- Python 3.10 以上與 `uv`。
- Linux desktop 使用固定版本 `pywebview==5.4` 的 GTK backend；Ubuntu 先安裝 `python3-gi`、`gir1.2-gtk-3.0`、`gir1.2-webkit2-4.1`，再執行 `uv venv --system-site-packages --allow-existing` 與 `uv sync`。
- pywebview 從 repository 相鄰的 `webview/index.html` 載入 `style.css` 與 `app.js`；不需要 HTTP server 或遠端資產。
- 「更新裝置」、「擷取畫面」和實際執行路徑需要已連線且已授權的 `adb` 裝置。

`--gui` 目前提供離線 capture/review/rules/search/execute 與 operations 工作區：更新裝置、選取序號、非同步擷取目前畫面、校正盤面、顯示 5×6 盤面 review、修正珠子、設定規則、背景路徑搜尋、候選核准、執行與安全停止；另可從相容性區匯入／匯出 Profile JSON，並在除錯區檢視操作狀態。原始截圖保持為 ground truth，含未知格、診斷候選或未核准候選時 controller 不允許執行。

規則控制變更會立即套用並清除舊候選；搜尋主控台只顯示後端實際回報的 attempts、conditions 或 max_combo 階段，可安全取消。只有目前已確認、符合條件且已核准的路徑可執行；執行前 Python 先完成目前盤面接受與低權重學習，再進入 ADB 手勢。執行中其他命令會被拒絕；停止要求會在目前手勢安全放手後生效，頂端狀態列與事件主控台會顯示實際階段及手勢後驗證結果。

## 2. 載入來源與校正

### Android 截圖

按「更新裝置」取得裝置清單，再選擇裝置並按「擷取畫面」。裝置清單、擷取與辨識在 Python 後端非同步執行；操作狀態會出現在頂端狀態列與事件主控台，不會鎖住盤面選取、規則、搜尋或主控台檢視。

### 盤面校正

在「盤面校正」區可輸入左上 X、左上 Y 與格寬後按「套用校正」，或按「自動校正」重新依來源尺寸推定。校正與擷取完成前會顯示進行中，成功或失敗會顯示可處理的後端訊息；擷取／校正中的盤面變更命令會安全拒絕，非衝突的狀態、選取與搜尋仍可用。

### 問號時主動重試

辨識若仍有 `unknown`，後端會以相同的原始截圖、寬高與校正重試，直到沒有問號或達到上限；不會重新擷取，也不會把中間錯誤結果當成學習資料。事件主控台與頂端狀態列會顯示實際辨識狀態；重試不保證改善，仍應檢查盤面。

## 3. 盤面檢視與修正

### 盤面檢視

標題列的「盤面」選單可在 6×5 標準盤面與 7×6 擴張盤面之間切換；切換會用同一張截圖重新辨識。執行區的「轉珠後」開關決定手勢送出後的行為：預設是**停手確認盤面**——仍按著珠子，讀回盤面與預期比對，必要時做保守修正再放手；關掉則是**直接放手**，不讀回盤面。直接放手少一次盤面讀取（WiFi adb 上是好幾秒），但沒有任何安全網：手勢若被遊戲吃掉或走位，程式不會知道，狀態也只會回報「已送出並直接放手，未做盤面確認」，不會宣稱驗證成功。CLI 對應 `--no-verify`。

盤面沒有問號時，右側盤面可選取任一格檢查；有 `unknown` 時，未知數量與選取格會固定顯示，控制器不允許確認或執行，直到每格被修正。

### 人工修正

選取盤面格後，在珠子面板選擇種類，再切換強化／鎖定標記並按「修正所選格」。修正未知格會自動前往下一個未知格；原始截圖保持不變，人工修正只更新受控盤面資料。可設定或清除保護格，搜尋與執行會遵守保護格。

## 4. 人工標記與學習資料

人工標記會立即更新目前盤面並寫入專案內：

```text
.pad-router/orb-prototypes.json
```

檔案只保存小型數值特徵與標籤，不保存截圖。寫入流程先在同一目錄建立暫存檔，成功後以 `Path.replace()` 原子取代正式檔；序列化、暫存寫入或取代失敗時，正式檔和記憶體中的樣本保持不變，錯誤會回到可處理的 `OSError`。

目前模型是不訓練的 CPU nearest-prototype 流程：

- Human Annotation 權重高於隱式低權重資料。
- 人工重新標記同一格且 feature 相同時，以新標籤取代舊樣本，避免矛盾樣本累積。
- 新截圖會利用已保存資料協助辨識，但相似度不足或類別不明時仍顯示 `?`；不要把自動結果視為無條件正確。

若需要清除本機學習資料，先關閉 GUI，再依專案管理政策處理 `.pad-router/orb-prototypes.json`；程式不提供復原或批次標記功能。

## 5. 規則設定與 Profile JSON

規則設定會在控制項變更後立即建立並套用 `RuleProfile`，不需要「建立」或「套用」兩步。可設定：

- 三組條件：不限、Combo 下限、指定屬性、同時指定屬性、指定 Match 數、連續珠數、強化珠、形狀與其他核心支援條件。
- 形狀條件的色珠：色珠一橫列、9 顆正方形、十字型、L 型、T 型與 4 顆消除等；十字型、L 型與 4 顆消除可選「不指定」。
- 條件關係：全部符合或任一符合。
- 危害珠策略：避免危害珠或允許危害珠。
- 外部條件：例如 HP 或技能條件已確認／未確認；程式不自行猜測這些畫面外條件。
- 消珠結算：計入落珠連鎖或只計轉珠直接消除。
- 搜尋嘗試次數、執行步數上限（預設 80）、隨機種子。最大 Combo 的瓶頸通常是步數而非嘗試次數：
  同一盤面把步數上限從 50 拉到 80，個別盤面可多 1 組 Combo。
- 選了特定消法時，搜尋會先把形狀排出來，再沿同一條路徑繼續衝 Combo，並保留已成立的 Match，不會為了 Combo 拆掉形狀。
- 問號重試次數：1–5，預設 2；此設定不寫入 Rule Profile JSON。

設定區的 inline 文案會顯示目前 Profile 已套用。相容性區的「匯出 JSON」會保留核心 `RuleProfile` schema；選擇 JSON 檔後按「匯入 JSON」會在背景套用設定並清除舊候選。JSON 欄位和值維持核心使用的英文識別碼，方便程式相容；Profile 匯入／匯出不改動原始截圖。

## 6. 評估與搜尋路徑

結果中的「直接」只計排盤完成當下的 Match；「預估」會先扣除指定消法，再按可用珠種的剩餘數量除以 3 計算。危害珠在策略允許時也會納入；落珠連鎖只保留在既有 Combo 顯示中，不影響最大 Combo 排名。

評估或搜尋後，結果下方會顯示「目標版型」：把本盤面的珠子照 3 顆一塊的參考排法重排後的完整盤面，以及該排法實際成立的 Combo 數。餘珠也會填進去，所以數字已經扣掉「餘珠把同色方塊接成一塊」的損失 —— 偏色盤面（例如某色 25 顆）會明顯低於「預估」。它是排盤目標，不保證單次拖珠一定排得出來。

確認盤面後可：

1. 調整搜尋固定選項後按「搜尋符合路徑」，查看符合條件的 Candidate Route；若找不到合格路徑，介面仍會顯示診斷候選與失敗條件。
2. 以盤面按鈕或方向鍵選取格子，檢查未知／強化／鎖定／保護標記；規則與路徑控制位於可收合區域，不會取代來源畫面。

Combo 下限條件的上限依盤面而定：6×5 為「至少 10 Combo（6×5 上限）」，7×6 為「至少 14 Combo（7×6 上限）」。
依 pazuma「最大火力配置：コンボ」的 2 色盤面表，6×5 只有在兩色各 15 顆、以 3 顆為一塊交錯排列時才能到 10 Combo；
7×6 的 42 顆珠同理在兩色各 21 顆時才能到 14 Combo（每 3 顆一直線鋪滿整個盤面）。珠種越偏，上限越低
（例如 6×5 的 25-5 只有 4 Combo）。
因此結果中的「預估」是庫存上限，不保證單次拖珠排得出來。

搜尋使用固定 seed 的有限束搜尋，不保證找到全域最大 Combo。候選不會用 Combo 數取代必要的隊伍條件；未指定珠種的 4 顆消除、L 型與十字型只需任一珠種有一組符合形狀的 Match，搜尋會優先保留符合形狀的候選，指定珠種仍只接受該珠種。一般條件束搜尋的同色珠距離勢能只是次級 tie-break，不能當成精確最佳性保證。

## 7. 執行路徑與驗證

「執行目前路徑」按鈕只有在目前候選可執行、盤面已確認、條件符合、已核准且有裝置序號時才啟用。按下按鈕即代表接受目前盤面；程式會先把目前盤面作為低權重學習資料寫入，再直接送出 ADB 路徑，不會再跳第二次確認視窗。

仍保留必要安全流程：校正座標、非空路徑、已確認盤面與核心 `play` 的手勢後盤面驗證。若學習資料寫入失敗，不會送出 ADB；若手勢後盤面沒有通過驗證，web workspace 會顯示失敗狀態，請重新擷取盤面後再規劃。

## 8. 常見處理

- **很多問號**：確認裝置畫面清晰、校正正確；先選格並修正，不要直接執行。
- **心珠／闇珠疑似互判**：選取盤面格後使用珠種控制重新標記；相似的後續截圖會使用永久特徵，但無法辨識時仍會拒判。
- **來源圖太大或太小**：使用來源面板捲動區域；顯示縮放不會改變原始校正座標或辨識結果。
- **無法執行**：檢查是否有符合條件的路徑、盤面是否仍有問號、裝置是否在清單中，以及校正是否有效；查看事件主控台的錯誤等級。
