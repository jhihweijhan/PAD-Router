# PAD Router 使用指南

這份指南給第一次使用桌面 GUI 的玩家；它說明如何在辨識不確定時安全修正、設定規則、搜尋路徑與執行手勢，維護者可再看[架構](../reference/architecture.md)與[開發指南](../reference/development.md)。

## 1. 啟動與準備

```bash
# Complete Tk board workflow (default --gui until cutover #14)
uv run python pad_router.py --gui

# Issue #10/#11 capture, review, and rules workspace (explicit opt-in)
uv run python pad_router.py --webview
```

需要：

- Python 3.10 以上與 `uv`；`--gui` 需要系統 Tk。
- `--webview` 需要固定版本 `pywebview==5.4`，以及 Ubuntu GTK/WebKit 套件。先執行：

  ```bash
  sudo apt-get update
  sudo apt-get install --yes python3-gi gir1.2-gtk-3.0 gir1.2-webkit2-4.1
  uv venv --system-site-packages --allow-existing
  uv sync
  ```

- 「更新裝置」、「擷取畫面」和實際執行路徑需要已連線且已授權的 `adb` 裝置。

`--webview` 目前提供 Issue #10/#11 的離線工作區：更新裝置、選取序號、非同步擷取目前畫面，顯示 5×6 盤面 review，並提供規則選擇與背景路徑搜尋。可點選或以方向鍵移動選取格，修正未知／疑似珠子，切換強化與鎖定標記，或設定／清除保護格；修正未知格會立即更新未知數量並前往下一格。原始截圖保持為 ground truth，含未知格時 controller 不允許確認，診斷候選明確標為不可核准／執行。

規則控制變更會立即套用並清除舊候選；搜尋主控台只顯示後端實際回報的 attempts、conditions 或 max_combo 階段，可安全取消。`--webview` 仍不提供執行路徑按鈕；完整執行流程適用於 Tk `--gui` 入口。

## 2. 載入來源與校正

### PNG

按「開啟 PNG」選擇截圖。GUI 只接受 PNG，會依截圖實際寬高推定 6×5 盤面校正；若推定不合適，使用「重新自動校正」或目前專案提供的校正流程重新指定盤面。

### Android 截圖

按「更新裝置」取得裝置清單，再選擇裝置並按「擷取畫面」。擷取與辨識使用同一份原始 BGRA 像素資料；來源圖在 Canvas 中可依視窗可視區域等比例縮放，顯示縮放不會改變校正座標或辨識結果。

### 問號時主動重試

「問號時主動重試」是唯讀選單，值為 1–5 次，預設 2；第一次辨識已包含在總次數內。每次辨識若仍有 `unknown`，系統會以相同的原始截圖、寬高與校正重新辨識，直到沒有問號或達到上限，不會重新擷取也不會把中間錯誤結果當成學習資料。狀態列會顯示「主動辨識第 X/Y 次」；重試不保證改善，仍應檢查盤面。

## 3. 認識三種操作模式

### 路徑模式（Ready）

盤面沒有問號時，介面顯示目前為路徑模式。拖曳右側可編輯盤面以建立手動路徑；也可按「搜尋」找符合規則的候選路徑。

### 檢視模式（有問號）

盤面有一格以上 `unknown` 時，GUI 會自動進入檢視模式，先選取需要回答的格子。按珠種按鈕或鍵盤 `1`–`0` 回答，完成一格後會前往下一個待回答格；全部修正後才可確認盤面。

### 修正模式（已辨識盤面）

HSV 或局部圖樣可能把心珠／闇珠等已辨識珠子判錯。Ready 狀態按「修正辨識」進入修正模式，此時點擊任何格子只會選取，不會開始路徑拖曳；再按珠種按鈕或 `1`–`0` 即可覆寫人工標記。強化與鎖定選項也適用於人工標記。

一次標記後可繼續選取其他格子；按「結束修正」回到路徑模式。介面文案會標示目前模式及回到路徑模式的方法。未知格仍優先使用檢視模式，不會和修正模式混用。

## 4. 人工標記與學習資料

人工標記會立即更新目前盤面並寫入專案內：

```text
.pad-router/orb-prototypes.json
```

檔案只保存小型數值特徵與標籤，不保存截圖。寫入流程先在同一目錄建立暫存檔，成功後以 `Path.replace()` 原子取代正式檔；序列化、暫存寫入或取代失敗時，正式檔和記憶體中的樣本保持不變，錯誤會回到可處理的 `OSError`。

目前模型是不訓練的 CPU nearest-prototype 流程：

- Human Annotation 權重高於隱式低權重資料。
- 人工重新標記同一格且 feature 相同時，以新標籤取代舊樣本，避免矛盾樣本累積。
- 新截圖會利用已保存資料協助辨識，但相似度不足或類別不明時仍顯示 `?`；不要把自動結果視為無條件正確。

若需要清除本機學習資料，先關閉 GUI，再依專案管理政策處理 `.pad-router/orb-prototypes.json`；程式不提供復原或批次標記功能。

## 5. 規則設定與 Profile JSON

規則設定會在控制項變更後立即建立並套用 `RuleProfile`，不需要「建立」或「套用」兩步。可設定：

- 三組條件：不限、Combo 下限、指定屬性、同時指定屬性、指定 Match 數、連續珠數、強化珠、形狀與其他核心支援條件。
- 形狀條件的色珠：色珠一橫列、9 顆正方形、十字型、L 型、T 型與 4 顆消除等；十字型、L 型與 4 顆消除可選「不指定」。
- 條件關係：全部符合或任一符合。
- 危害珠策略：避免危害珠或允許危害珠。
- 外部條件：例如 HP 或技能條件已確認／未確認；程式不自行猜測這些畫面外條件。
- 消珠結算：計入落珠連鎖或只計轉珠直接消除。
- 搜尋嘗試次數、執行步數上限（預設 80）、隨機種子。最大 Combo 的瓶頸通常是步數而非嘗試次數：
  同一盤面把步數上限從 50 拉到 80，個別盤面可多 1 組 Combo。
- 選了特定消法時，搜尋會先把形狀排出來，再沿同一條路徑繼續衝 Combo，並保留已成立的 Match，不會為了 Combo 拆掉形狀。
- 問號重試次數：1–5，預設 2；此設定不寫入 Rule Profile JSON。

設定區的 inline 文案會顯示目前 Profile 已套用。按「儲存 JSON」保存目前已套用的 Profile；按「載入 JSON」後，controller/state 與可由 GUI 表達的條件、顏色、關係、危害策略及外部條件控制值會同步。JSON 欄位和值維持核心使用的英文識別碼，方便程式相容。

## 6. 評估與搜尋路徑

結果中的「直接」只計排盤完成當下的 Match；「預估」會先扣除指定消法，再按可用珠種的剩餘數量除以 3 計算。危害珠在策略允許時也會納入；落珠連鎖只保留在既有 Combo 顯示中，不影響最大 Combo 排名。

評估或搜尋後，結果下方會顯示「目標版型」：把本盤面的珠子照 3 顆一塊的參考排法重排後的完整盤面，以及該排法實際成立的 Combo 數。餘珠也會填進去，所以數字已經扣掉「餘珠把同色方塊接成一塊」的損失 —— 偏色盤面（例如某色 25 顆）會明顯低於「預估」。它是排盤目標，不保證單次拖珠一定排得出來。

確認盤面後可：

1. 直接在可編輯盤面拖曳，完成後查看 Match、cascade、Combo、危害與條件結果。
2. 調整搜尋固定選項後按「搜尋」，查看符合條件的 Candidate Route；若找不到合格路徑，介面仍會顯示診斷候選與失敗條件。

Combo 下限條件最高可選「至少 10 Combo（5x6 上限）」：依 pazuma「最大火力配置：コンボ」的 2 色盤面表，
5x6 只有在兩色各 15 顆、以 3 顆為一塊交錯排列時才能到 10 Combo；珠種越偏，上限越低（例如 25-5 只有 4 Combo）。
因此結果中的「預估」是庫存上限，不保證單次拖珠排得出來。

搜尋使用固定 seed 的有限束搜尋，不保證找到全域最大 Combo。候選不會用 Combo 數取代必要的隊伍條件；未指定珠種的 4 顆消除、L 型與十字型只需任一珠種有一組符合形狀的 Match，搜尋會優先保留符合形狀的候選，指定珠種仍只接受該珠種。一般條件束搜尋的同色珠距離勢能只是次級 tie-break，不能當成精確最佳性保證。

## 7. 執行路徑與驗證

「執行路徑」按鈕只有在目前候選可執行、盤面已確認、條件符合且有裝置序號時才啟用。按下按鈕即代表接受目前盤面；程式會先把目前盤面作為低權重學習資料寫入，再直接送出 ADB 路徑，不會再跳第二次確認視窗。

仍保留必要安全流程：校正座標、非空路徑、已確認盤面與核心 `play` 的手勢後盤面驗證。若學習資料寫入失敗，不會送出 ADB；若手勢後盤面沒有通過驗證，GUI 會顯示失敗狀態，請重新擷取盤面後再規劃。

## 8. 常見處理

- **很多問號**：確認截圖清晰、校正正確；先回答或進入修正模式，不要直接執行。
- **心珠／闇珠疑似互判**：Ready 時按「修正辨識」，選格後重新標記；相似的後續截圖會使用永久特徵，但無法辨識時仍會拒判。
- **來源圖太大或太小**：調整 Tk 視窗；來源 Canvas 會保持長寬比重新顯示，必要時可用 Canvas 捲動區域。
- **無法執行**：檢查是否有符合條件的路徑、盤面是否仍有問號、裝置是否在清單中，以及校正是否有效。
